# Backend Email Setup (Gmail SMTP)

This guide explains how the backend team can configure Gmail to send customer email-verification messages.

## Important security notes

- SMTP credentials belong only in the backend environment. Never collect them in the frontend or expose them through a frontend `VITE_` variable.
- Do not commit `.env` files, App Passwords, or SMTP credentials to Git, and do not paste them into chat or issue trackers.
- Use a Google App Password, not the Gmail account's normal password.
- If an App Password has been exposed, revoke it in Google Account settings and generate a replacement.

## Generate a Google App Password

1. Sign in to the Google account that will send the emails. The account must match `SMTP_USER`.
2. Enable 2-Step Verification for that Google account if it is not already enabled.
3. Open [Google App Passwords](https://myaccount.google.com/apppasswords).
4. Create an App Password for this application (for example, name it `Restaurant app`).
5. Copy the generated 16-character password. Google may display it in groups; the groups are just for readability.

If Google does not offer App Passwords, check the account's 2-Step Verification and security policies. Some managed or restricted accounts do not permit App Passwords; use an organization-approved SMTP provider in that case.

## Configure the project

Edit the project-root `.env` file, beside `docker-compose.yml`. Do not put these settings in frontend source code or `Frontend/.env`.

```env
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=sender-address@gmail.com
SMTP_PASS=the-16-character-app-password
SMTP_SECURE=false
SMTP_FROM=sender-address@gmail.com
```

Replace the example sender address with the Gmail address used to generate the App Password. Replace the password with the generated code. Do not include surrounding quotes or explanatory text. Spaces in the displayed App Password are optional; the application removes whitespace.

The root `.env` is used by Docker Compose to configure the backend container. Keep it local and private. Confirm it is ignored by Git before adding or editing any secrets:

```powershell
git check-ignore .env
```

If that command does not report that `.env` is ignored, stop and ensure the file is not staged or committed. Do not add secrets to `.env.example`; that file should contain placeholders only.

## Apply the configuration

From the project root, recreate the backend container so it receives the latest environment values:

```powershell
docker compose up -d --force-recreate backend
```

If backend code or dependencies have also changed, rebuild it:

```powershell
docker compose up -d --build backend
```

## Verify delivery safely

1. On the verification page, use **Resend verification email**.
2. If sending fails, inspect recent backend logs:

   ```powershell
   docker compose logs --since 10m --no-color backend
   ```

3. Never share unredacted logs if they contain email addresses, tokens, or other sensitive values.

Common SMTP errors:

- **`EAUTH` / `535 5.7.8 BadCredentials`**: Gmail rejected authentication. Confirm `SMTP_USER` is the full sender Gmail address and `SMTP_PASS` is a current App Password generated by that same account. Do not use the normal Gmail password. Check for accidental extra characters when editing `.env`.
- **Connection or timeout errors**: Check the SMTP host/port, network access from the server, and whether outbound SMTP is blocked by the hosting environment.
- **The app says the email was sent, but it is not in the inbox**: Check Spam and other inbox categories, and confirm the recipient address is correct.

After changing credentials, recreate the backend container and resend. Never print the App Password to verify it; check only whether the variable is present.

## When the customer clicks the email link
1. It opens the app’s Verify Email page at /verify-email?token=....
2. The page automatically sends the one-time token to the backend. If it’s valid and not expired, the page shows “Email verified” and a Continue to login button.
3. The customer clicks that button to go to customer login and sign in. Verification doesn’t automatically log them in.
4. If the link is invalid or expired, the page explains that and offers a way to request another one.
